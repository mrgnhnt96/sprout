=== F-03 — the ping survives revali build, so a dead peer is reclaimed ===
Transport-level frame capture on a real loopback socket:
        +15.0s  <-- PING, opcode 9
The annotation's 15s now reaches the generated route: .revali/server/routes/
__tree_route.dart carries `ping: Duration(microseconds: 15000000)`, where before
the fix the WebSocketRoute had no `ping:` argument at all. F-03 is fixed.

=== BUT: a new defect this exposes — see F-06 in docs/02-open-findings.md ===
A client that answers the ping with a well-formed masked pong is closed anyway:
        +15.0s  ping -> client sent pong
        +30.0s  CLOSE frame, code 1001, empty reason
Same result with a client that never pongs. The teardown fires at 2x the ping
interval regardless of whether the peer is alive, so the ping reclaims dead
sockets and healthy ones alike. Pre-fix, a socket was held 40.0s and never
closed (the Phase 2 proof), so the close is new with this change.
