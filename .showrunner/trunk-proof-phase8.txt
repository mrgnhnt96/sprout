1. THERE IS NO INGEST VERB TO REGISTER

   $ sprout --help
     run        Spawn one claude -p session at depth 0 and stream its events to disk.
     snapshot   Print the whole tree at one cursor: ...
     ui         Start the daemon and print the URL the board is at. ...
     watch      Stream deltas against a snapshot: ...

   $ sprout hook < /dev/null
   Could not find a command named "hook".
   exit=64

   Note the exit code. 64 from a PreToolUse hook is a DENIED TOOL CALL, and 2 from a Stop
   hook traps the session in a loop with the hook's stderr injected into the conversation
   (17-observed-schemas.md §7). Registering today's binary as a hook would not merely fail
   to observe — it would break the session it was pointed at.

   $ SPROUT_DB=<fresh> sprout snapshot
   cursor s1.1bca0197c52f7b41.0

   A whole session lived and died. The tree is empty, and the daemon is not at fault: there
   is no path by which a session sprout did not spawn can reach the store at all. sprout

reading of the code:

    and it waits out its own threshold before it does.

    not from the session dying.


4. A knob caveat worth writing down, measured on the way
---------------------------------------------------------
capture: .showrunner/phase8-captures/trunk-watchdog/after-trunk-stop-cont-thinking-turn.txt

An earlier trunk run stopped a session that was mid-THINKING-turn rather than mid-tool-
call: no tool use, one 18.1s API call. It rang `stalled` at 13s and 17s frozen, and on
CONT the model emitted its answer, the count reset, Stop and SessionEnd fired.

The ring was correct for the threshold it was given — the process was genuinely
suspended — but the run makes the shape of the measure explicit: transcript growth is
the only liveness signal for a hook-observed node, and a model that thinks for longer
than `frozenAfter` without writing looks exactly like a frozen one. At the demo's 12s
that is reachable by an ordinary turn; at the shipped default of 5 minutes it is not.
This is a property of the knob, already documented as a knob in `watchdogFrozenAfter`,
not a new finding — but it is now measured rather than assumed.
