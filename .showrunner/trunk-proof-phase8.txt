PHASE 8 BASELINE — what sprout sees of a session it did not spawn, BEFORE hook ingest
=====================================================================================

Binary under test : built from trunk dc7ce7d ("docs: Phase 6 proved on trunk"), the commit
                    this phase starts from. 8,621,936 bytes.
                    Pipeline: dart pub get; dart run revali build; dart compile exe.
Method            : a REAL Claude Code session, started by hand the way a developer starts
                    one — sprout did not launch it and owns no pipe to it — run to completion
                    in its own directory, with SPROUT_DB pointed at a fresh database.

1. THERE IS NO INGEST VERB TO REGISTER

   $ sprout --help
     run        Spawn one claude -p session at depth 0 and stream its events to disk.
     snapshot   Print the whole tree at one cursor: ...
     ui         Start the daemon and print the URL the board is at. ...
     watch      Stream deltas against a snapshot: ...

   $ sprout hook < /dev/null
   Could not find a command named "hook".
   exit=64

   Note the exit code. 64 from a PreToolUse hook is a DENIED TOOL CALL, and 2 from a Stop
   hook traps the session in a loop with the hook's stderr injected into the conversation
   (17-observed-schemas.md §7). Registering today's binary as a hook would not merely fail
   to observe — it would break the session it was pointed at.

2. THE SESSION RAN, AND SPROUT SAW NOTHING

   $ claude -p "reply with the single word BASELINE" --output-format stream-json --verbose
   session_id 981fb54e-f3f5-419b-acc3-9c6e9d5d24a5
   result     BASELINE
   cost       $0.19722
   exit=0

   $ SPROUT_DB=<fresh> sprout snapshot
   cursor s1.1bca0197c52f7b41.0
   no nodes
   holds nothing
   journal readable

   A whole session lived and died. The tree is empty, and the daemon is not at fault: there
   is no path by which a session sprout did not spawn can reach the store at all. sprout
   sees only what it launched and parses the stream-json of.

This is the "before" the phase is measured against. Artifacts:
  session.ndjson      the full stream of the unobserved session
  snapshot-after.txt  the empty tree, captured after it finished
Phase 8 — the ingest half, against the COMPILED binary, on a session sprout did not spawn

                Then reply with the single word ROOT."
       --settings <the block above> --permission-mode bypassPermissions

3. IT IS ON THE BOARD

   $ sprout snapshot
   cursor s1.5032866865c76fe7.14
   checkpointed · hook/4cf59fc2-bd5b-464b-939c-46774e4ae408 · Use the Task tool to launch
     exactly one subagent with subagent_type general-purpose whose prompt is: reply with
     the single word CHILD. Then reply with the single word ROOT. · since 23:48Z (0m)

       · next NONE SCHEDULED · spend ?
   holds nothing
   journal readable

   Two nodes, correctly parented. The root's task is the developer's own prompt. The child
   is the subagent, found by `agent_id` and attached by the PostToolUse join — the parent
   link that does not exist until the spawning tool call returns.

   Compare BASELINE.txt, same probe, previous commit: "no nodes / holds nothing".

4. WHAT THE STORE HOLDS

   1  hook.SessionStart        1  hook.PreToolUse       2  runner.observed
   1  hook.UserPromptSubmit    1  hook.PostToolUse      4  runner.updated
   1  hook.SubagentStart       1  hook.Stop
   1  hook.SubagentStop        1  hook.SessionEnd

   node  hook/4cf59fc2-…                     parent NULL          checkpointed
   node  hook/4cf59fc2-…/a4c468a39865c2ede   parent hook/4cf59…   checkpointed

   Every hook event is in the feed; the six runner.observed/updated are the store
   announcing its own rows, so a consumer holding a snapshot plus deltas learns of both
   nodes without taking a second snapshot.

5. AND THE BYTES ARE DURABLE BEFORE ANY OF THAT

   hooks.raw, beside the database, 24 lines = 8 records framed header/payload/blank:

     sprout-hook 2026-09-02T23:48:45.743037Z 469
     {"session_id":"4cf59fc2-…","transcript_path":"…","cwd":"…",
      "hook_event_name":"SessionStart","source":"startup"}

   Written before anything parses them (F-15's repair), so a payload the store cannot take
   — one with no session_id, or bytes that are not JSON — is still on disk.

P8-04 proof — the watchdog measures a session sprout did not spawn
=================================================================
Crawler crawler-p804-p8-04-watchdog-foreign-sessions, 2026-09-02.
Branch showrunner/p8-04-watchdog-foreign-sessions.

Everything below is a real run on this machine. Nothing is stubbed: real
`claude -p` processes, real hook payloads, a real `ps`, a real `stat`, the
shipped Watchdog.


1. CLAUDE_PID, measured first-hand
----------------------------------
docs/research/17-observed-schemas.md §9 claims the hook environment carries
CLAUDE_PID. The Phase 0 fixtures do not contain the env.txt files that would
have proved it, so it was measured rather than believed — twice.

  (a) orchestrator's capture, CLI 2.1.258 — scratch/pidprobe/, scratch/killprobe/
  (b) this Crawler's own capture, CLI 2.1.259 — scratch/p804-pidprobe/

(b), in full. A settings file registering six events, a hook that dumped
`env | grep '^CLAUDE'` and ran `ps -o pid=,ppid=,command= -p "$CLAUDE_PID"`,
against `claude -p "reply with the single word P804PROBE" --model haiku`:

  events fired: SessionStart, UserPromptSubmit, Stop, SessionEnd
  CLAUDE_PID=52305                     on all four, identical
  CLAUDE_CODE_SESSION_ID=dc765771-9bf4-4d0e-a0f9-46bf57167b25
  session_id in every payload           = dc765771-9bf4-4d0e-a0f9-46bf57167b25
  CLAUDE_CODE_EXECPATH=/Users/…/versions/2.1.259

  $ ps -o pid=,ppid=,command= -p 52305
  52305 52303 /Users/…/.local/bin/claude -p reply with the single word P804PROBE …
  hookshell_pid=52329 hookshell_ppid=52305

So CLAUDE_PID is the `claude` process itself and the hook shell's own parent —
not the hook, not a wrapper. transcript_path was the root session's .jsonl on
every one of the four.


2. A killed session fires no ending — measured
----------------------------------------------
From the orchestrator's killprobe capture (scratch/killprobe/), a session killed
mid-turn with kill -9 produced exactly:

  1788389785.973  SessionStart
  1788389786.369  UserPromptSubmit
        (kill -9 at ~6s, mid-turn)
  process gone — no Stop, no SessionEnd

The same prompt allowed to finish produced SessionStart, UserPromptSubmit,
PreToolUse, PostToolUse, Stop, SessionEnd. So a closed terminal leaves a
hook-observed root `working` forever with a dead pid, which is `abandoned`.
What the ring cap does with that is measured in section 4 and recorded as F-20.


3. THE DEMONSTRATION — a foreign session stalls, and the watchdog rings
-----------------------------------------------------------------------
A real Phase 0 hook capture (A/SessionStart, A/UserPromptSubmit) with its
session id and transcript path pointed at the demo's own files, folded through
the shipped HookProjection with CLAUDE_PID naming a real live process that
writes nothing. Program: scratch/demo/demo.dart. Verbatim output:

  a session sprout did NOT spawn, pid 15925
  node   hook/demo-0000-4000-8000-000000000804
  status working
  feed   runner.observed, process.observed, hook.SessionStart, runner.updated, hook.UserPromptSubmit
  
  --- immediately, while the transcript is fresh ---
  live: pid 15925 is alive and started at 2026-09-03 00:06:59.000Z; the transcript last grew 0s ago (threshold 3s ago)
  
  --- after 4s of silence (threshold 3s) ---
  RING   hook/demo-0000-4000-8000-000000000804 is stalled (ring 1) — pid 15925 is alive and started at 2026-09-03 00:06:59.000Z; the transcript last grew 4s ago (threshold 3s ago)
  sweep  rang for 1 of 1 node(s): hook/demo-0000-4000-8000-000000000804 stalled

Read the feed line: `process.observed` sits beside the `hook.*` payload rows and
there is no `runner.spawned` anywhere — the feed does not claim sprout launched
this process, and the measurement still works.

BEFORE — the same program, unchanged, run against the MAIN CHECKOUT at
391b691 (P8-03 merged, this leaf not applied), whose HookProjection has no
`environment` parameter and so cannot learn a pid. scratch/before/. Verbatim:

  a session sprout did NOT spawn, pid 19469
  node   hook/demo-0000-4000-8000-000000000804
  status working
  feed   runner.observed, hook.SessionStart, runner.updated, hook.UserPromptSubmit
  
  --- immediately, while the transcript is fresh ---
  abandoned: no runner.spawned event for this node, and no ending recorded
  
  --- after 4s of silence (threshold 3s) ---
  RING   hook/demo-0000-4000-8000-000000000804 is abandoned (ring 1) — no runner.spawned event for this node, and no ending recorded

That is the gap this leaf closes, and it was worse than "cannot measure": the
watchdog rang `abandoned` at a session that was alive and healthy, on the
strength of having no record rather than of any observation — because
`LivenessMeasure._newestSpawn` matched only `runner.spawned`, so every
hook-observed node fell through to `_whyNotStarted`.
