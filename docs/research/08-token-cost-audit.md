# Token cost audit — measured from local transcripts

**Corpus:** 343 `.jsonl` transcripts across 223 project directories, 499.4 MB, 204,656 records,
0 parse failures. Window `2026-08-27T03:52Z` → `2026-09-01T04:14Z` (5.01 days). 27,171 billed
assistant turns. Generated by `docs/research/tools/cost-audit.py`.

**Method.**

- *Counting rule.* A streaming transcript writes **one `type=="assistant"` record per content-block
  group**, and every record from the same API request carries the **same `message.id`, the same
  `requestId`, and a byte-identical `message.usage`**. Verified: 4,721/4,721 duplicate `requestId`s
  in a 60-file probe had identical usage and identical `message.id`. **Usage is therefore counted
  once per distinct `message.id`.** Naive per-record summing inflates every number by **2.02×**
  (27,171 counted vs 27,487 duplicates discarded — 27,257 same-file, 230 cross-file from resumed
  sessions). Every figure below uses the deduped count.
- *Pricing.* Anthropic first-party API list price. 99.8% of turns are `claude-opus-5`
  ($5.00 in / $25.00 out per MTok); cache write 1.25× input (5 min TTL) / **2.0× (1 h TTL)**;
  cache read 0.1× input. `claude-sonnet-5` and `claude-haiku-4-5` appear in trace amounts.
  Only 3 `<synthetic>` turns are unpriced (they carry no usage).
- *Lanes.* `isSidechain` **does not** separate multi-agent spend in this Claude Code version.
  Measured layout: Task-tool subagents live in `<project>/<session>/subagents/agent-*.jsonl`
  (`isSidechain: true` on exactly those records, 26 files); **showrunner Crawlers are full Claude
  Code sessions in git worktrees, so Claude Code files them as their own top-level project dirs
  containing `--worktrees-`** — 204 of 223 project dirs, 207 of 343 files. Three lanes:
  `main` / `crawler` / `subagent`.
- *Content attribution* is by serialized UTF-8 byte length of content blocks, converted to tokens
  at 4 bytes/token where a token figure is needed. Those conversions are marked **[estimated]**.

**Confidence.** Token counts, dollar amounts, cache ratios, lane splits, session/campaign costs and
turn-gap distributions are **measured** from `message.usage` and record structure. Byte-to-token
conversions for injected context and thinking signatures are **[estimated]**. System-prompt and
tool-schema sizes are **not in the transcripts at all** and are not reported as such — the first-turn
cache-write figure is used as their observable proxy. Totals drift ~0.1% between runs because this
audit's own session is appending to the corpus while it reads.

## Headline numbers

**Fresh input tokens are 0.01% of the bill. 65% of every dollar is spent re-reading cache.**

| Billing component | Tokens | $ | % of spend |
|---|---:|---:|---:|
| Cache **read** | 4,014,021,718 | **$2,004.58** | **65.0%** |
| Cache **write** (58.85M @ 1 h + 2.49M @ 5 min) | 61,341,376 | $601.38 | 19.5% |
| Output | 19,188,488 | $479.30 | 15.5% |
| Fresh (uncached) input | **54,574** | **$0.27** | **0.01%** |
| **Total** | **4,094,606,156** | **$3,085.53** | 100% |

| Metric | Value |
|---|---|
| Effective cache hit rate — `cr / (cr + cw + in)` | **98.49%** |
| Mean context re-read per turn | **147,732 tokens** |
| Mean cost per turn | $0.1136 |
| Spend rate | **$615.87 / day** over 5.01 days |
| Sessions | 315 (median $5.73, mean $9.77, p90 $25.35, max $60.98) |
| Compaction events in the entire corpus | **0** |

Cache is already near-optimal at 98.49%; there is no meaningful hit-rate win left. The cost is
**volume**: 4.01 billion cache-read tokens is the whole story, and it is driven by context length
multiplied by turn count, not by cache misses.

By model: `claude-opus-5` $3,083.4 (99.9%), `claude-sonnet-5` $1.92, `claude-haiku-4-5` <$0.01.
There is effectively **no model tiering on this machine** — everything runs on Opus.

## Main thread vs subagents

| Lane | Sessions | Turns | Cache read | Cost | % of spend | Hit rate |
|---|---:|---:|---:|---:|---:|---:|
| `main` (base-repo sessions) | 108 | 12,983 | 2.344 B | $1,698.46 | 55.1% | 98.73% |
| `crawler` (showrunner worktree sessions) | 207 | 13,657 | 1.634 B | **$1,356.92** | **43.98%** | 98.27% |
| `subagent` (Task-tool sidechains) | 26 | 531 | 35.6 M | $30.15 | 0.98% | 93.46% |

**44.95% of all spend is on spawned agents** — and almost all of it (43.98 pts) is showrunner
Crawlers, not Task subagents. Anyone auditing this machine by `isSidechain` alone would conclude
subagents cost 1% of the bill and be wrong by a factor of 46.

**Subagent (Task sidechain) size distribution**, n=26: median **898,197 tokens / $0.79 / 16 turns**;
p90 2.65 M / $2.06 / 29 turns; max 6.69 M / $4.08 / 72 turns. Zero single-turn subagents — the
cheapest still ran a full loop.

**Crawler session distribution**, n=207: median $4.89, mean $6.56, p90 $11.50, max $45.52,
mean 66.0 turns.

### Do spawned agents re-pay for a cold prefix? — the number that matters for sprout

| Lane | n | 1st-turn cache **read** (median) | 1st-turn cache **write** (median) | Fully cold 1st turns |
|---|---:|---:|---:|---:|
| `main` | 108 | **0** | 46,845 | **75.9%** (82/108) |
| `crawler` | 207 | **10,010** | 29,900 | **0.0%** (0/207) |
| `subagent` | 26 | 15,883 | 15,073 | 34.6% (9/26) |

**Answer: partially — and the part that is re-paid is small.** Every one of the 207 Crawler spawns
got a cache hit on its first turn (~10 K tokens, the machine-wide harness prefix that was already
warm from a sibling), and then wrote a median 29,900 fresh tokens for its own repo-specific
prefix. Total spawn tax across all 207 Crawlers: **$63.06 (2.0% of corpus spend)**, ≈ **$0.30 per
spawn**, which is **6.1% of the median Crawler's $4.89 lifetime cost**.

The cold-prefix penalty is real but it is *not* the dominant cost of recursion on this machine.
A Crawler's cost is its 66-turn lifetime, not its birth. Ironically the *main* sessions start
colder than Crawlers do — 75.9% fully cold, median 46,845 write tokens, $44.55 total — because
Crawlers spawn in bursts and warm each other's shared prefix.

## Where the input tokens come from

There are essentially no fresh input tokens ($0.27 total). The real question is **what fills the
context that then gets re-read 147,732 tokens per turn**. By serialized content-block bytes:

| Block type | Bytes | % | Count |
|---|---:|---:|---:|
| `tool_result` | 116.28 MB | 63.8% | 29,446 |
| `thinking` (signature blobs only) | **32.12 MB** | **17.6%** | 16,107 |
| `tool_use` (the call arguments) | 23.00 MB | 12.6% | 29,451 |
| `image` (top-level) | 5.95 MB | 3.3% | 28 |
| `text` (assistant prose) | 4.94 MB | 2.7% | 9,383 |

**Correction that matters:** of the 116.28 MB of `tool_result`, **71.86 MB (61.8%) is base64 image
data** from 271 screenshot-returning `Read` calls. **Base64 bytes are not proportional to image
tokens** (images bill ≈ w·h/750), so ranking tools by raw bytes is misleading. Ranked by **text**
bytes only (44.42 MB):

| Tool | Text bytes | % of text results | Calls | Mean |
|---|---:|---:|---:|---:|
| **Bash** | **41.02 MB** | **92.3%** | 26,751 | 1,533 B |
| Read (text) | 1.26 MB | 2.9% | 175 | 7.2 KB |
| WebFetch | 1.03 MB | 2.3% | 334 | 3.1 KB |
| WebSearch | 0.51 MB | 1.2% | 171 | 3.0 KB |
| Edit | 0.20 MB | 0.5% | 801 | 251 B |

**Bash is 92% of everything the model reads back**, and it is *not* a few big dumps: median Bash
result 595 B, p90 3,978 B, **max 29,915 B**. Every one of the 259 tool results ≥32 KB is an image.
There are no oversized text dumps in this corpus — this machine's `CLAUDE.md` steers work through
Bash with `head`/`sed -n`, and it worked. It is death by 26,751 small cuts.

**Thinking blocks.** 16,107 blocks; **visible thinking text = 0 bytes** (Opus 5 defaults to
`display: "omitted"`), but each carries an opaque `signature` blob, median 1,272 B, **32.12 MB
total ≈ 8.03 M tokens [estimated]**. That is the second-largest thing in context — 72% as large as
all text tool output combined — and it is semantically worthless to the reader. It cannot be
dropped (signatures must be replayed unchanged on the same model), but it should be budgeted for.

**Hook- and harness-injected context**, per session:

| Injection | Occurrences | Total bytes | Mean |
|---|---:|---:|---:|
| `skill_listing` (the available-skills block) | 392 | **10.24 MB** | 26,115 B (≈6.5 K tok) |
| `SessionStart` hook stdout | 532 | 4.51 MB | 8,475 B |
| `hook_additional_context` | 943 | 1.60 MB | 1,692 B |
| `total_tokens_reminder` | 26,339 | 1.29 MB | 49 B |
| `PreToolUse` hook stdout | 38,778 | 2.05 MB | 52 B |

Total injected: **16.40 MB ≈ 4.10 M tokens [estimated]**, median 48,941 B per session. Because it
lands early in the prompt it is written once and then **cache-read on every subsequent turn of that
session**. Amortized: **$257.09 (8.3% of spend) [estimated]** — of which the skill listing alone is
≈$160 and SessionStart hooks ≈$71.

**System prompt / tool schemas / CLAUDE.md are not present in the transcripts** and cannot be sized
directly. Their observable proxy is the first-turn cache write on a fully cold `main` session:
**median 46,845 tokens**.

## Multi-agent runs — the measured multiplier

Crawlers were attributed to their orchestrator by repo + timestamp containment: 203 of 207 Crawlers
(98.1%) fell inside exactly one base-repo session's time span. That yields **49 identified
campaigns**.

| | Value |
|---|---:|
| Campaigns | 49 |
| Crawlers per campaign | median **3**, max **17** |
| Campaign cost | median **$33.82**, mean $47.73, max **$164.07** |
| Orchestrator's share of its own campaign | **42.4%** |
| Baseline: base-repo session that never invoked showrunner (n=25) | median **$2.21** |
| Baseline: any non-campaign session (n=59) | median $4.04 |
| **Multiplier vs plain session** | **15.3×** |
| Multiplier vs any non-campaign session | 8.4× |

**The measured multiplier on this machine is 15.3×** against a plain single-threaded session —
which lands almost exactly on the published ~15× figure, arrived at independently. Against a
looser baseline (any session not running a campaign, including heavy solo work) it is 8.4×. Both
should be quoted; the honest range is **8–15×**, and the spread is entirely about what you call a
"normal session".

**Where the campaign money went — and where it did not.** The orchestrator is not cheap
coordination overhead on top of cheap workers: it is **42.4% of the campaign by itself**.
Orchestrator sessions are the most expensive class in the corpus (n=83, median $12.83, mean $18.13,
**mean 136.3 turns**) while Crawlers are comparatively cheap (median $4.89, mean 66.0 turns).
The orchestrator runs twice as long as any worker it spawns.

Duplicated context across Crawlers was measured and is **negligible**: identical Bash command
strings executed in 2+ different Crawler sessions of the same repo account for **853,795 bytes
≈ 213 K tokens [estimated]** total (1.1–1.6% of distinct commands per repo). Worktree isolation
means Crawlers genuinely do not re-do each other's reads. Cross-Crawler duplication is *not* a
cost problem here.

## Waste patterns, priced

Ranked by dollars. Note that four of the "usual suspects" measured to approximately zero — that is
a finding, not an omission.

### 1. Context accumulation over long sessions — **$683.61 (22.2% of spend)**

Per-turn cost rises monotonically with turn index because every turn re-reads the whole conversation:

| Turn range | Turns | Mean cache read / turn | Mean $/turn | $ | % of spend |
|---|---:|---:|---:|---:|---:|
| 1–25 | 7,558 | 67,672 | $0.0884 | $668.36 | 21.7% |
| 26–50 | 6,176 | 111,839 | $0.0896 | $553.59 | 17.9% |
| 51–100 | 6,622 | 158,943 | $0.1122 | $742.94 | 24.1% |
| 101–200 | 4,868 | 241,696 | $0.1549 | $753.96 | 24.4% |
| **201+** | 1,947 | **299,296** | **$0.1883** | $366.68 | 11.9% |

A turn past #200 costs **2.13×** a turn in the first 25. **60.4% of all spend happens after turn
50.** Counterfactual: if every turn had cost the 1–25 rate, the corpus would have cost $2,401.92 —
so **$683.61 is attributable purely to context growth**.

*Fix:* hand off at a turn budget. Handing off at turn 50 would have moved 13,437 turns from
$1,863.58 to $1,187.83, a gross saving of **$675.75**; ~268 extra session starts at the observed
$0.47 cold-prefix cost gives back ~$126, for a **net ≈ $550 (17.8%) [estimated]**. This is by far
the largest single lever.

### 2. Harness-injected context, amortized across every turn — **$257.09 (8.3%) [estimated]**

16.40 MB / ≈4.10 M tokens of skill listings, SessionStart hook output and additional-context blocks
are written once per session then cache-read on every turn of that session. The `skill_listing`
block alone (26,115 B ≈ 6.5 K tokens per injection) is ≈$160. *Fix:* inject the skill listing and
SessionStart context **once per prefix, not once per spawned agent**, and prune it to the skills a
given agent can actually use. A Crawler that will only run tests does not need 60 skill
descriptions in its prefix for 66 turns.

### 3. The 1-hour cache TTL premium — **$220.68 (7.2%)**

Every `main` and `crawler` cache write in the corpus uses the **1 h TTL (2.0× input)**; only the
Task subagents use 5 min (1.25×). 58,849,321 tokens written at 1 h cost **$588.49**; the same
writes at 5 min would cost $367.81.

Measured turn gaps say the premium mostly does not pay: median gap between consecutive turns
**8.6 s**, p90 34.5 s, p99 606.5 s — only **1.75% of gaps exceed 5 minutes** and **0.12% exceed
60 minutes**. *Caveat:* the 1 h TTL also protects a prefix across a whole campaign, and re-writing
an expired prefix costs full freight, so the true saving is less than $220.68. But at 98.25% of
turns arriving inside the 5-minute window, this is a lever worth measuring rather than assuming.

### 4. Failed / retried tool calls — **≈$100 (3.2%) [estimated]**

881 `tool_result` blocks with `is_error: true` — **2.99% of all 29,451 tool calls** — 539,611 bytes.
830 of 881 (94.2%) are Bash. Priced at the corpus mean turn cost, the wasted round trips are
≈$100.05; the error text also stays in context and is re-read for the rest of the session.

### 5. Cold prefix on spawn — **$63.06 (2.0%)**

207 Crawler spawns wrote 6,197,070 fresh prefix tokens (median 29,900 each, $0.30 each). Real, but
an order of magnitude below the context-growth lever. Not worth contorting the design for.

### 6. Measured and found negligible — do not build fixes for these

| Pattern | Measured | Verdict |
|---|---|---|
| Oversized tool dumps | 259 results ≥32 KB — **all 259 are images**; max text result 29,915 B | non-issue |
| Same file re-read in a session | 50 redundant of 445 `Read` calls (11.2%), but `Read` text is 2.9% of text bytes | <$5 |
| Identical Bash command re-run in a session | 188 of 26,751 calls (0.70%), 90,335 B | <$1 |
| Byte-identical tool results repeated | 55 occurrences, 83,689 B (0.07%) | <$1 |
| Cross-Crawler duplicated work | 853,795 B ≈ 213 K tokens across 7 repos | <$3 |
| Prefix churn / avoidable cache misses | 98.49% hit rate corpus-wide; no lane below 93% | none found |
| Compaction events | **0 in 343 files** | never triggered |

## What this means for sprout

1. **Budget by turns, not by agents.** Cost is `turns × context_size`, and context size grows
   monotonically. A depth-3 tree of 10 short agents is cheaper than one agent running 300 turns.
   sprout should meter a run in **turn-budget**, and the natural unit is ~50 turns — the point past
   which measured per-turn cost begins climbing (from $0.089 to $0.112 and up to $0.188).

2. **Make hand-off a first-class primitive, and fire it automatically.** This is a **$550/5-day
   [estimated]** lever on this machine's workload — 17.8% of spend — larger than every other lever
   combined. sprout should force a checkpoint-and-respawn when an agent crosses its turn budget,
   carrying forward a written handoff rather than the raw transcript. The corpus shows this never
   happens today: 1,947 turns ran past #200, and **compaction fired zero times in 343 sessions**, so
   nothing is currently bounding context growth at all.

3. **Do not fear the spawn — fear the prefix you hand it.** Spawning is cheap ($0.30, 2.0% of
   spend, and 0% of Crawler spawns were fully cold). What is expensive is that each spawned agent
   carries ~48 KB of injected harness context and ~47 K tokens of prefix for its entire life.
   **sprout should assemble a per-role minimal prefix at spawn time** — only the skills, hooks and
   CLAUDE.md sections that role needs — because that prefix is multiplied by the agent's turn count,
   not paid once.

4. **Spawn siblings in bursts, on a shared prefix.** Every Crawler in this corpus hit a warm
   ~10 K-token prefix because siblings launched close together; solo `main` sessions started fully
   cold 75.9% of the time. sprout should **batch spawns within the cache TTL window** and order a
   wave's agents so the shared prefix is written once and read 
   N−1 times. This is already working accidentally; sprout should make it deliberate.

5. **Cap the orchestrator harder than the workers.** The orchestrator is **42.4% of campaign cost**
   and runs 136 turns to a Crawler's 66. sprout's coordinator must not accumulate the workers'
   output in its own context. Workers should return **fixed-size structured summaries**, and the
   coordinator should be the first thing sprout hands off when its turn budget trips.

6. **Set the cache TTL per role, not globally.** 5 min for tight agent loops (98.25% of turns arrive
   within 5 min — the 2× write premium buys nothing there); 1 h only for a coordinator that
   genuinely idles while workers run. Blanket 1 h TTL cost **$220.68 (7.2%)** here.

7. **Route by model — nothing does today.** 99.9% of spend is Opus 5. Reading-heavy leaf work
   (test runs, greps, lint sweeps, status polls) has no measured need for Opus. sprout should
   default **leaf agents to a cheaper model and lower effort**, and reserve Opus for the coordinator
   and for work that measurably needs it. This is unquantified from these transcripts because the
   experiment was never run — it is the highest-value thing to measure next.

8. **Budget for the thinking tax.** 32.12 MB ≈ **8.03 M tokens [estimated]** of opaque thinking
   signatures sit in these contexts and get re-read every turn. They cannot be stripped on the same
   model. sprout's context-size accounting must include them or it will under-predict by ~15%.

9. **Refuse: unbounded recursion depth without a turn budget at each level.** Depth 3 with a 50-turn
   budget per level is bounded work. Depth 3 with no budget is 3 nested copies of the $683 problem.
   sprout should refuse to spawn a child that inherits no budget.

10. **Refuse: spawning an agent to do one tool call.** Median Task subagent burned 898,197 tokens
    over 16 turns and **zero of 26 were single-turn**. A spawn that is not worth ≥10 turns should be
    an inline tool call. The floor cost of a spawned agent on this machine is ~$0.62.

11. **Do not spend engineering on tool-output hygiene.** Oversized dumps, duplicate reads, repeated
    commands and cross-agent duplication together measure **under $10 of $3,085 (0.3%)**. The
    discipline already in this machine's CLAUDE.md is working. sprout should preserve it (cap Bash
    output, prefer `head`/`sed -n`) and then stop optimizing there.

12. **Instrument from day one, and dedupe by `message.id`.** Any cost telemetry sprout emits must
    apply the counting rule in the Method section or it will report 2.02× the real number. Also:
    **do not use `isSidechain` to find spawned-agent spend** — on this Claude Code version it misses
    98% of it, because worktree agents are filed as independent top-level projects.

## Method notes and caveats

- **The window is 5 days, not a lifetime.** Every transcript on this machine falls in
  2026-08-27 → 2026-09-01. Conclusions describe this machine's *current* working style (heavy
  showrunner campaigns, Bash-first tooling, all-Opus) and may not generalize to earlier or later
  periods. Nothing here is extrapolated to a longer window.
- **Dollar figures are API list price.** If this work ran on a Claude Code subscription the cash
  outlay differs; the figures are correct as a measure of consumed value and for relative ranking,
  which is what the design questions turn on.
- **Campaign attribution is heuristic.** Crawlers were matched to orchestrators by repo plus
  timestamp containment. 203/207 matched uniquely; 4 were unattributable. A transcript field
  explicitly linking a Crawler to its spawning session would remove the heuristic — showrunner
  could emit one.
- **The 15.3× multiplier rests on a 25-session baseline.** "Base-repo sessions that never invoked
  showrunner" is a small and possibly unrepresentative comparison group (median $2.21 — these may
  simply be shorter tasks). The 8.4× figure against all non-campaign sessions is the conservative
  bound. A controlled A/B — the same task run solo and via showrunner — is the only way to tighten
  this, and no such pair exists in the corpus.
- **Byte→token conversion at 4 bytes/token is a convention, not a measurement.** Everything derived
  from it is marked [estimated]. `messages.count_tokens` against reconstructed prompts would make
  the injected-context and thinking-signature figures exact; that requires replaying prompts, which
  this read-only audit did not do.
- **System prompt, tool schemas and CLAUDE.md are absent from the transcripts.** The 46,845-token
  cold first-turn write is their combined observable proxy, not a direct measurement, and it also
  includes the first user message.
- **Image token cost is not measured.** 271 screenshot results contributed 71.86 MB of base64 but
  bill on pixel dimensions, which the transcript does not record. They are excluded from all
  text-byte rankings rather than approximated.
- **The audit's own session is in the corpus** and was still writing during the run; totals move
  ~0.1% between executions. Re-run `docs/research/tools/cost-audit.py` to regenerate.
