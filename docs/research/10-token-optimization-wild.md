## Context compression

**Token-level compression does not survive contact with code.** LLMLingua's headline is "up to 20× with minimal performance loss" **[A]**; LongLLMLingua reports +21.4% on NaturalQuestions at ~4× fewer tokens and 94% cost cut on LooGLE **[A]**. On code the picture inverts. CodePromptZip (arXiv 2502.14925) benchmarks them directly:

| Task | LLMLingua | LongLLMLingua | LLMLingua-2 | CodePromptZip |
|---|---|---|---|---|
| Assertion generation (EM %) | 33.8 | 34.1 | **21.2** | 42.1 |
| Bugs2Fix (CodeBLEU %) | 41.9 | 42.1 | 48.1 | 61.9 |

LLMLingua-2 — the newest and most promoted variant — is the *worst* on assertion generation. Cause: code token classes (identifiers, symbols, signatures, structure) carry task-dependent importance that NL-trained entropy models can't see. ShortenDoc (2410.22793) corroborates: SOTA compressors manage only ~10% reduction on code docstrings before quality breaks.

Two more nails. **Maintenance:** `microsoft/LLMLingua` has 6.6k stars but its PyPI package's last release was **2024-04-09** — over two years — despite ~90k downloads/month. **Reproduction:** [issue #146](https://github.com/microsoft/LLMLingua/issues/146) reports LLMLingua-2's LongBench *baseline* is ~6 points lower in the paper than in reproduction (paper 24.5 uncompressed vs reproducer 30.3), which would make the "compression is free" framing an artifact of a weak baseline. **The issue is open with no maintainer reply.** That is a serious mark against the most-cited technique in this space.

Soft-prompt compression (Gist Tokens 26×, AutoCompressor ~41×, ICAE ~15×, 500xCompressor up to 480×, xRAG 1 token/doc) is **categorically inapplicable** to sprout: every one requires model weights. And 500xCompressor's own headline retention is **62.3–72.9%** of uncompressed capability — catastrophic for code.

The one broad cross-method study (arXiv 2505.00019, 13 datasets) concludes ~0.5 compression is the sweet spot and that **"all methods increase hallucinations, primarily through information loss"** and *"even seemingly uninformative words affect output quality."*

**What actually ships instead.** Two things, both cheap:

1. **Structural eviction with no model call.** Anthropic's context editing clears stale tool results at a threshold: **84% token reduction on a 100-turn web-search eval**, and it turned runs that previously failed on context exhaustion into completions; +39% over baseline combined with the memory tool **[A]**. Claude Code's "microcompact" tier does the same locally (keeps recent tool results, replaces older ones with a placeholder) — community-reverse-engineered, not vendor-confirmed. OpenAI's Codex ships `compact_token_budget.rs` which its own comments say **skips model/server summarization** entirely. Cline dedupes repeat file reads with a `[DUPLICATE FILE READ]` marker.
2. **LLM summarization**, which is the expensive tier and the one with real quality cost.

**The cost of compaction is under-reported.** It is a full-context read plus 1–4k output. Roo Code's docs give the only concrete public figure: **$0.33 for one condense** on Grok-4. And it can go backwards — Codex [issue #7232](https://github.com/openai/codex/issues/7232) documents `/compact` taking a user from 70% to **100% of a 272K limit (328K used)**, i.e. compaction *added* ~56k tokens.

**The quality cost of compaction is measurable and bad.** Governance Decay (arXiv 2606.22528; 1,323 episodes, 7 models, 9 tasks): with the policy visible and no compaction, **0% constraint violations**. After compaction, **30% pooled** (DeepSeek 0→59%, GPT 0→41%). Conditioned on survival: **constraint survived the summary → 0% violation (n=90); constraint dropped → 38% violation (n=315).** Soft policies decayed 8.3× more than hard safety norms. For sprout this is directly actionable: whatever a child *must not* do has to be re-injected after every compaction, never merely summarized.

**Delta-updates instead of rewrites.** ACE (arXiv 2510.04618, Zhang et al.) argues monolithic rewriting causes "context collapse" — iterative summarization erodes detail and imposes brevity bias. Their fix: represent context as itemized bullets and apply small localized deltas merged by non-LLM logic. Reported +10.6% on agent benchmarks and +8.6% on finance **[A]**; the abstract says latency and rollout cost drop "significantly" without giving a percentage — treat the cost claim as unquantified.

**Cache-aware compaction.** TokenPilot (arXiv 2606.17016, EMNLP 2026 Findings) names the exact tension sprout will hit: pruning context changes the prefix and **invalidates the KV cache**, so naive compression can cost more than it saves. Their two-level answer (stabilize the prefix at ingestion, evict only when a segment's relevance expires) reports **61%/56%** cost cut isolated and **61%/87%** continuous, competitive quality **[A]**.

**Baseline reality check.** Chroma's Context Rot study (18 models, incl. GPT-4.1, Claude 4, Gemini 2.5, Qwen3) is the best independent evidence **[M]**: degradation starts far below the advertised window, is non-uniform, and worsens with distractors. Their LongMemEval result is the number to design around — a **~300-token focused prompt vs the ~113k full prompt** shows a substantial accuracy gap in *every* model family, largest for Claude. The lesson is not "compress the context" — it is **never let it get big**.

## Sub-agent cost control

**The multiplier is real and published.** Anthropic: "agents typically use about 4× more tokens than chat interactions" and "multi-agent systems use about 15× more tokens than chats" **[A]**. Their conclusion is an economic gate, not an engineering one: multi-agent "require[s] tasks where the value of the task is high enough to pay for the increased performance," and is a bad fit where agents "share the same context or involve many dependencies."

**The output contract is explicit and it is the single cleanest pattern here.** From Anthropic's context-engineering post, verbatim: *"Each subagent might explore extensively, using tens of thousands of tokens or more, but returns only a condensed, distilled summary of its work (often 1,000-2,000 tokens)."* In the research system, subagents "act as intelligent filters." This is cheaper *and* better: the parent's context stays small, so context rot never sets in on the orchestrator — the one agent whose judgment matters most. **[A]**, but the mechanism is corroborated independently by Chroma's focused-vs-full result.

**Spawn thresholds are published as concrete tiers.** Anthropic gives the lead agent explicit budget guidance, verbatim:
- simple fact-finding → **1 agent, 3–10 tool calls**
- direct comparison → **2–4 subagents, 10–15 calls each**
- complex research → **10+ subagents with clearly divided responsibilities**

Stated purpose: *"prevent overinvestment in simple queries."* This is the most directly transplantable thing in the entire literature for sprout, because sprout owns the spawn decision.

**Cognition's arc is worth reading in order.** ["Don't Build Multi-Agents"](https://cognition.com/blog/dont-build-multi-agents) gives two principles: *"Share context, and share full agent traces, not just individual messages"* and *"Actions carry implicit decisions, and conflicting decisions carry bad results."* Their Flappy Bird example — one subagent builds a Mario background, another builds a mismatched bird — is the canonical failure. Their follow-up, ["Multi-Agents: What's Actually Working"](https://cognition.com/blog/multi-agents-working), narrows to one rule: **multiple agents contribute intelligence; writes stay single-threaded.** Two patterns they ship:
- **Code review loop** — reviewer keeps a *completely clean context*, deliberately not sharing the coder's history. Catches ~2 bugs/PR, **58% classified severe [A]**. Their reasoning is the interesting part: the shorter context *improves* detection, because attention is finite.
- **"Smart friend"** — primary model escalates to a stronger model. Honest negative: *"SWE 1.5 was not good enough at being the primary model for this setup to really work"* — the escalation decision itself requires a frontier model.

**Fork-style subagents that inherit the parent's cache.** Qwen Code documents a `fork` subagent mode where *"All forks share the parent's exact API request prefix (system prompt, tools, conversation history), enabling prompt cache hits"* — claimed **80%+ token cost reduction vs independent subagents [C, no methodology]**. `fork_turns` bounds how much history is inherited. Contrast with Claude Code subagents, which start cold: community reporting puts a spawn's cold-start tax at ~3,500 tokens (system prompt + CLAUDE.md + tool schemas) **[C, asserted not measured]**, and Anthropic's own docs note agent teams in plan mode can run ~7× a normal session. **For sprout this is a design fork worth taking seriously:** a child that shares the parent's prefix reads at 0.1× instead of paying full price to re-establish identical context.

**Break-even heuristics found in the wild** (all asserted, none validated — treat as starting hypotheses): spawn only above ~10,000 input tokens of work; abandon delegation if `overhead_tokens / work_tokens > 0.3`; a subagent's output must be summarizable to <2k tokens or it shouldn't have been a subagent. One practitioner reports **60% lower token cost** from restructuring Opus-orchestrator/Sonnet-workers into Sonnet-orchestrator + Opus-writer + Haiku-searchers **[C, one person's pipeline]**.

**The harness itself is a bigger variable than most people assume.** Claw-SWE-Bench (arXiv 2606.12344, 350 instances, 8 languages, 43 repos) made the harness a controlled variable and found **model choice changes Pass@1 by 29.4 pp; harness choice changes it by 27.4 pp under fixed models** — and that "systems with similar accuracy can differ substantially in total API cost." Same paper: the same harness with a minimal vs full adapter went **19.1% → 73.4% Pass@1**. **[M]** This is the best available justification for sprout existing at all, and the best warning that a badly-wired harness silently destroys a good model.

**Simple scaffolds are cost-competitive.** `SWE-agent/mini-swe-agent` (6.9k stars, active) scores **>74% on SWE-bench Verified in ~100 lines of Python with bash as its only tool**, at roughly **$0.30/instance [A]**. Recent leaderboard entries put it at 75.8% for ~$0.07/instance. The lesson for a harness author: complexity in the scaffold is not free, and is frequently not paying for itself.

## Retrieval instead of stuffing

**The headline finding: the dominant designs in this space have no published evidence.** Aider's repo map, Claude Code's grep-first stance, Cline's "we don't index" post, and serena all publish exactly zero measurements. The consensus is architectural taste plus one unpublished internal A/B at Anthropic. That is worth knowing before copying any of them.

**Aider's repo map** (source: `aider/repomap.py`, 867 lines) is the reference design and is genuinely clever: tree-sitter extracts defs/refs → a `networkx` graph of files with ident-reference edges → **personalized PageRank** → rank distributed onto individual tags → binary search over the tag list to fill a token budget. Ranking weights from source: ×10 if the user mentioned the ident, ×10 for long snake/camel names, ×0.1 for `_`-private, ×0.1 if defined in >5 files, ×50 if the referencing file is already in chat. Default budget: **1k tokens** (×2 when no files are in chat) standing in for an entire repo.

But: [aider.chat/docs/repomap.html](https://aider.chat/docs/repomap.html) and the 2023 writeup give **no before/after token count and no benchmark delta for map-on vs map-off**. The 1k is a *budget*, not a saving. The FAQ concedes *"weaker models get easily overwhelmed and confused by the content of the repo map."* And the project has stalled — 48.6k stars but last release v0.86.0 (2025-08-09), last commit 2026-05-22. **Reference architecture, not a living project.**

**Anthropic's position, sourced.** Boris Cherny: *"Early versions of Claude Code used RAG + a local vector db, but we found pretty quickly that agentic search generally works better… doesn't have the same issues around security, privacy, staleness, and reliability."* The "outperformed everything, by a lot" line traces to a podcast, not a published eval. The engineering blog gives the framework (just-in-time loading, lightweight identifiers, progressive disclosure) and honestly concedes *"runtime exploration is slower than retrieving pre-computed data."* No numbers anywhere.

**Cline's post contains zero numbers** — three arguments (chunking breaks logic, index staleness, embeddings duplicate IP) and no data. More interesting: Cline's actual position is not *cheap* context, it's *full* context. Their engineer's framing is that **RAG is a cost optimization for flat-rate $20/mo vendors** (Cursor named) that a BYO-API-key tool doesn't need. That reframes the whole debate — it is a pricing-model argument wearing a quality-argument costume.

**The independent benchmarks favor dumb tools.** ContextBench (arXiv 2602.05892; 1,136 tasks, 66 repos, 8 languages, gold context annotations): **mini-SWE-Agent — a plain bash loop — has the best File F1 at 0.634**, while embedding-based Agentless scores 0.390 and graph-based Prometheus 0.403 **[M]**. Cost/instance: GPT-5 $0.45 (5.87 steps), Claude Sonnet 4.5 $0.76 (14.38 steps, best Line F1 0.530, Pass@1 0.720). They also find a large "context usage drop" — agents retrieve the right code and then fail to use it, which is a *different* problem from retrieval. Agentless (arXiv 2407.01489) resolves 27.33% of SWE-bench Lite at **$0.34/issue** with no index at all. CORE-Bench (2606.11864) shows embedding retrievers collapsing from snippet matching to agentic localization: Qwen3-8B **71.7 → 20.3**.

**The counter-evidence is narrower than it looks but not nothing.** Cursor's semantic search post **[A, vendor]**: +12.5% mean accuracy on a *private* benchmark, but the online A/B — the number that matters — is **+0.3% code retention overall, +2.6% on repos ≥1,000 files**. SWE-QA (arXiv 2608.01507; 720 questions, 15 repos, 13K–861K LOC) is the strongest pro-embedding result: **semantic 65.2% vs deep-agentic grep 46.2%**, at **$0.32 vs $0.74 per correct answer**, input tokens 34k vs 761k — but it is read-only Q&A, not patch generation. Notably it also found **41.8% of agentic failures were silent planner↔subagent handoff losses**, which is a direct warning for sprout's own topology. Windsurf's "200% recall, 40× faster, 1000× cheaper" and Augment's "70%+ quality improvement" have no methodology — discard.

**Nobody has published a controlled grep-vs-embedding comparison on patch generation in a >100K-file repo.** That is the only setting where the answer is non-obvious, and it is empty.

**LSP vs grep, ablated** (arXiv 2608.13568, single author, small n): tokens-to-success — Opus **920 grep vs 971 LSP**; Sonnet **606 vs 1,319 (+118%)**; Haiku **11,911 vs 8,799 (−26%)**. LSP wins on reference completeness (F1 0.778, precision 1.00 vs 0.706/0.76) at +19% tokens, but **grep wins multi-file rename outright (pass@1 1.00 vs 0.67–0.83)**. Given free choice, agents used semantic tools **0–6%** of the time for localization. The pattern matches Aider's repo-map caveat exactly, inverted: **semantic tooling saves tokens only for weak models.** For a harness running frontier models, grep is both cheaper and better.

**The honest lesson on "cheap".** grepai's own self-benchmark (n=5, Excalidraw 155K LOC) reports input tokens **51,147 → 1,326 (−97%)** but the actual bill **$6.78 → $4.92 (−27.5%)**. Cache-creation tokens dominate. **Anyone quoting token-count savings without cache accounting is overstating cost savings by ~3.5×** — including several entries in this document, which is why the [M]/[A] labels matter.

## Caching beyond prompt caching

**Prompt caching is the baseline, and it is hard to beat.** Verified against current official docs (2026-08/09):

- **Anthropic** — cache write **1.25×** base input (5-min TTL) or **2×** (1-hour); cache read **0.1×**. TTL **refreshes free on every read**, measured from request *start*. Max **4 breakpoints**; automatic top-level caching consumes one. Minimum cacheable prefix is **not monotonic across model generations** (Opus 5 = 512 tokens; Sonnet 5 / Opus 4.8 = 1024; Opus 4.7 / Haiku 3.5 = 2048; Opus 4.6/4.5 / Haiku 4.5 = 4096) — a real footgun for a harness that switches models per child. Invalidation is tiered prefix-match: tools → system → messages, so **changing a tool definition or the model invalidates everything**; changing thinking/effort always invalidates messages. No long-context premium: a 900K request bills at the same per-token rate as 9K. Anthropic's "up to 90% cost reduction" is the 0.1× multiplier restated — marketing, not an independent finding.
- **OpenAI** — **90% discount for the GPT-5 family** (the widely-cited "50%" is stale GPT-4o-era). Automatic. Min 1,024 tokens (GPT-5.6+), 128-token increments, ~30 min retention. Output always full price.
- **Gemini** — implicit caching on by default for 2.5+ (the "90%" figure traces to a social post, not docs). Explicit `CachedContent` bills **storage per MTok-hour whether or not you hit it** ($1.00/MTok-hr for 2.5 Flash, $4.50 for 2.5 Pro) — a gotcha the other two don't have.

**The rules that actually move hit rate** (and that a harness can enforce mechanically, which is why this is sprout's #1 lever):
- Byte-identical prefix. Manus: *"even a single-token difference can invalidate the cache from that token onward."* No timestamps, UUIDs, or session IDs before the breakpoint.
- Tools render at position 0 on all three APIs — **never reorder or conditionally include tool definitions**.
- Serialize JSON with deterministic key order. Non-deterministic map ordering is a silent, total invalidator.
- Anthropic applies a **20-content-block lookback per breakpoint** — heavy tool loops silently miss.
- N parallel requests with an identical prefix all miss, because none can read what the others are still writing. Stagger by one token or one request.
- Manus reports a **100:1 input:output token ratio** in production agents and calls KV-cache hit rate *"the single most important metric for a production-stage AI agent"* — with cached vs uncached at a **10× price difference [A]**.
- Corollary: **mask tools, don't remove them.** Manus masks token logits during decoding to constrain which tools are selectable, rather than editing the tool list, precisely because editing it destroys the cache and confuses the model about prior actions.

**Semantic caching: skip it.** `zilliztech/GPTCache` (8.2k stars) is effectively dead — last commit 2025-07-11, last release Aug 2024, 97 open issues, and its "10× cost / 100× speed" README claim has **zero supporting benchmark in the repo**. Vendor hit-rate claims are self-reported and incoherent (Helicone: "20–30% typical, up to 95%"; Portkey: "~20% at 99% accuracy," and Portkey caps semantic cache at ≤4 messages / <8,191 tokens, which architecturally excludes agent contexts). The decisive evidence is a maintainer admission, not marketing: **LiteLLM's own docs state semantic caching is a poor fit for multi-turn or agentic workloads**, because sequential-turn embeddings collapse into near-duplicates of the prior turn and replay stale answers.

For code it is worse. A one-token diff — a line number, a path, a variable name — demands a different answer, and that is exactly what cosine similarity cannot see. vCache (arXiv 2502.03771, Berkeley/Stanford/TUM) shows static similarity thresholds carry **no correctness guarantee at all** and proposes learned per-prompt thresholds with verified error bounds (up to 12.5× hit rate, 26× lower error vs static **[A]**). There is also an attack surface: [Key Collision Attack on Semantic Caching](https://arxiv.org/html/2601.23088v1) crafts inputs that collide in embedding space to poison or exfiltrate cached responses. And the silent killer nobody markets: **swapping the embedding model invalidates the cache semantically** and starts serving confidently-wrong answers with no error signal.

Honest production hit rates are **20–45%**, not 90%+. The "95%" figures usually measure *match accuracy*, not *hit frequency*.

**Deterministic tool-result caching: boring, safe, underused.** This is the version that works.
- `LangGraph` ships node-level `CachePolicy`, key = hash of node input, configurable TTL.
- `DSPy` caches LM calls by default (memory + disk), keyed on request params.
- `CrewAI` has `cache=True` plus a programmable `cache_function(args, result) -> bool` for custom invalidation.
- `smolagents` and LlamaIndex have **no** built-in tool cache — docs tell you to roll your own.
- TVCACHE (arXiv 2602.10986) is the research shape sprout wants: tool-result caching with **stateful invalidation tied to world-state changes** — "same command + same repo state = same answer." Prototype, not production.
- A SWE-bench measurement study (Local-Splitter, arXiv 2604.12301) attributes the reliable part of a combined 65% token reduction to **exact-match memoization**, with semantic caching contributing only 20–35% and being explicitly flagged as risky where "code tasks require exact matching or precise state information."

For a coding harness the invalidation key is available and cheap: `(command, cwd, git rev-parse HEAD, dirty-file hashes)`. That is a real, correct cache key — and sprout, unlike a generic framework, can compute it.

**Plan caching by intent.** Agentic Plan Caching (arXiv 2506.14852) caches *plan templates* keyed on an extracted intent keyword and adapts them with a cheap model: **50.31% average cost reduction, 27.28% latency reduction, performance maintained [A]**. Benchmarks are unnamed in the abstract — treat as promising, unverified.

## Model cascades and routing

**Query-level routing has much weaker evidence than its reputation.** RouteLLM (`lm-sys/RouteLLM`, 5.4k stars, **last push 2024-08-10 — dead for two years**) reports >85% cost reduction on MT Bench and 45% on MMLU while retaining 95% of GPT-4 performance **[A]**. The authors' own admitted caveats matter more than the headline: routers trained on Arena data perform at **near-random level out-of-distribution** (MMLU); the framework is two-model only; and — their words — *"performance between different routers trained on the same dataset can vary widely on the same benchmark without a clear explanation."*

FrugalGPT (Chen/Zaharia/Zou, arXiv 2305.05176) is the source of the famous **"up to 98% cost reduction"** figure. It is a best case on narrow classification-shaped workloads, from 2023 prices and models, requiring labeled in-distribution training data that drifts continuously in production. **Do not plan against 98%.**

**The independent number is ~35%, not 85%.** RouterArena (arXiv 2510.00202; ~8,400 queries, 9 domains) evaluated NotDiamond, Azure Model Router, GraphRouter, CARROT, RouterDC, IRT-Router, RouteLLM, vLLM Semantic Router: **no router ranks top across all metrics, and most over-rely on the strongest model, missing cheap-defer opportunities.** Only vLLM-SR and CARROT reached ~35% lower cost at <2% accuracy loss; all fall short of oracle. NotDiamond ranks **#12 at $4.10 per 1,000 queries** — it keeps picking expensive models. That directly contradicts vendor marketing (Martian: "up to 98%"; NotDiamond: "10×"), none of which is independently reproduced.

**Routing is also adversarially removable.** "Rerouting LLM Routers" (arXiv 2501.01818, COLM 2025) shows query-independent "confounder gadgets" appended to any query force routing to the strong model with **near-100% attack success**, white- *and* black-box, on open-source and commercial routers, with no visible quality change — **up to 2× inference cost**. Less relevant to a single-user harness, but it means the routers are not robust in the way their marketing implies.

**What actually works is the architectural cascade, not the classifier.** Strong model plans, cheap model executes:

**The most sprout-relevant datapoint** is RLM-Cascade (arXiv 2606.22840, PayPal): response-level speculative decoding on a **real Claude Code agentic coding workload**, 125 production requests. DeepSeek-V4-Pro drafts, Claude Opus verifies, an O(1) rule-based router decides, tool calls carved out. **88.8% draft-use rate, 45.8% cost reduction vs direct Opus**, 1.83× p50 speedup, 100% vs 95% pass on a 20-task benchmark **[A]**. Honest caveats they state: **TTFT is 2.1× worse** (draft-then-verify is sequential), one task cost *more* when Opus expanded a short wrong draft, and router false-negatives carry quality risk while false-positives only cost money. Small n, vendor-adjacent, but it is the closest thing to sprout's actual workload in the literature.

AI21 reports a similar shape **[A, vendor]**: MiniMax-M3 explores, GPT-5.2 extracts context, a frontier model patches → **80.8% on SWE-Bench Pro at $5.99/task** vs solo frontier at $18.28/task, with frontier models consuming only 25% of the budget.

**Discount aggressively:** the 2026 SEO cluster quoting suspiciously precise figures ("Opus 4.8→Sonnet 4.6 saves 28%," "three-tier routing saves 51%," "Cursor Router 60% lower cost") has no published methodology. Likewise Claude Code issue #44976's "$2,000–3,000/month savings, 60–70% of tokens wasted on Opus" is a user's feature-request estimate, not a measurement.

**Break-even:** if router cost > (escalation rate avoided) × (price gap), routing loses money. Below roughly 1,000 calls/month the absolute saving doesn't repay the integration.

## Output-side savings

**Output is where the money is.** Anthropic output is exactly **5× input** across the line (Opus 5 $5/$25, Sonnet 5 $2/$10, Haiku 4.5 $1/$5); GPT-5 is ~8×. Meanwhile Manus reports a **100:1 input:output ratio** in production agents — so output is a small share of *tokens* but a meaningful share of *cost*, and it is the axis a harness can compress without touching correctness of input.

**Structured output does not save output tokens. That premise is wrong.** `The sentiment is positive` = 5 tokens; `{"sentiment":"positive"}` = 7 — **JSON is ~40% more** for small payloads, and full structured responses run 2–3× a free-text summary. Savings come from **eliminating prose scaffolding**, not from the format: SymCode emitting code instead of chain-of-thought went 2,991 → 699 output tokens (60–77% cut) **[A]**. **No rigorous study measures "JSON vs prose output tokens" as its own variable** — the token case for structured output is a-priori reasoning, not measurement.

**The "structured output hurts reasoning" debate is resolved — against the original paper.** Tam et al., *Let Me Speak Freely?* (EMNLP 2024 Industry) reported catastrophic drops: Claude-3-Haiku GSM8K **86.51% → 23.44%** (−63.1pp), GPT-3.5 76.60 → 49.25. But classification went the *other* way (DDXPlus Gemini 41.59 → **60.36**, +18.8pp). The .txt rebuttal re-ran it with fair prompts and got **structured winning across the board** (GSM8K 0.77→0.78, Last Letter 0.73→0.77), and identified three methodological faults: the paper conflated **JSON-mode with constrained decoding**, used different prompts for the two arms (never showing the model the schema), and used an LLM as its answer parser — which scored 57% where a hand-written regex got 61%, i.e. the measuring instrument was lossy. .txt's separate GSM8K study across 8 models found structured generation improving results in *all* cases, up to **>70% lift** (MetaMath-Tulpar 18.9% → 71.1%).

**The usable rule:** constrained decoding is safe-to-positive; JSON-mode-by-prompting on a weak model is genuinely dangerous. And **field order matters** — put a `reasoning` field before the answer field or you lose the reasoning benefit.

**Reasoning effort has a steep, measurable diminishing return.** Artificial Analysis on GPT-5 **[M, independent]**: Intelligence Index **high 68 / medium 67 / low 64 / minimal 44**, at **82M tokens for high vs 3.5M for minimal — 23×**. One index point between medium and high costs 78M tokens. Their own summary: *"between medium and high there is less of an uplift."*

**Overthinking is measurable and it costs money.** Cuadron et al., *The Danger of Overthinking* (arXiv 2502.08235) — **3,908 trajectories, 19 models, SWE-bench Verified [M]**. Overthinking score correlates *negatively* with resolution (reasoning models β₁ = −7.894, R² = 0.892, p<0.001). Reasoning models overthink more (3.505 ± 1.774 vs 2.228 ± 0.751). Concretely: **o1 low effort = 21.0% at $400; o1 high = 29.1% at $1,400** — 3.5× the cost for +8.1pp. Two fixes they measured, both directly usable by a harness:
1. **Run k=2 at low effort and keep the lower-overthinking trajectory → 27.3% at $800** (43% cheaper than high effort); **k=3 → 30.3%, beating high effort at 15% less cost.**
2. **Native function calling took o1-high from 29.1% → 47.7%** while dropping overthinking 2.43 → 1.05. This is the single largest cheaper-and-better result in this entire document, and it costs nothing to adopt — it is a choice of tool-call channel, not a technique.

**Anthropic's own effort guidance** now lives in `output_config.effort` (5 levels; extended thinking's explicit budget is deprecated). It affects **all** tokens including tool calls — *"lower effort would mean Claude makes fewer tool calls"* — and the docs **explicitly recommend `low` for subagents**. On Opus 4.7 they note `max` "on some structured-output or less intelligence-sensitive tasks it can lead to overthinking." For sprout, which sets the model and effort for every child, this is a one-line default with a large multiplier.

**Verbosity control is cheap and measured.** OpenAI's cookbook, `verbosity` low/medium/high output tokens: poem **560 / 849 / 1,288**; coding **575 / 943 / 2,381** — roughly linear **[A]**. CCoT (arXiv 2401.05618): "be concise" + step-by-step cuts response length **48.7%** for **−2.95pp (GPT-3.5) / +0.25pp (GPT-4)**, neither significant, **22.7% cost saving** — but GPT-3.5 lost **27.7% on math**, so the tax lands on weak models. TALE (arXiv 2412.18547): injecting an *estimated token budget* into the prompt cuts output **68.6%** for −2.72pp accuracy and ~59% cost; GSM8K-Zero went 252.96 → **22.67** output tokens at 98.72% accuracy **[A]**.

**Stop conditions: the most honest negative result in this document.** BAGEN, *Are LLM Agents Budget-Aware?* (arXiv 2606.00198; rollout-replay over Sokoban, Search-R1, SWE-bench, a warehouse sim, 5 frontier models) **[M]**. Naive early-stop-on-predicted-infeasibility **saves 28–64% of tokens on failed trajectories for 1.6–4.2pp success loss** (GPT-5.2 saved 64% but false-aborted 6.6%; Opus saved 28% at 2.2%). The catch is fatal to the naive design: **all 20 model-environment pairs are systematically optimistic.** Models still predict >70% feasibility after burning 60% of their budget, and reliable failure prediction only arrives in the last 20% — too late to save anything. Feasibility prediction is a *calibration* problem (SFT takes Qwen-7B from 25.5% to ~90%); interval estimation is a *reasoning* problem with a low ceiling (10.5% → 47% coverage). **Do not ask a child "can you finish?" and trust the answer.** Brave's AgentStop (arXiv 2605.15206, ACM AIAS 2026) takes the external route instead — a supervisor kills unpromising runs from token-level logprobs, **15–20% wasted energy saved at <5% utility drop [M]** — which is the shape a harness should copy.

**Productized budgets exist but are advisory.** Anthropic's `task_budget` beta injects a **server-side countdown the model can see**, so it paces itself; `max_tokens` remains the only hard cap. Minimum 20,000. Two documented footguns: a too-small budget produces **refusal-like behavior and premature scope-down**, and mutating the remaining-budget value client-side **invalidates prompt cache every turn**. Not available inside Claude Code. Framework state of the art elsewhere is a dumb counter — LangGraph's `recursion_limit` defaults to 25 super-steps. Claude Code's `--max-budget-usd` (print mode, v2.1.217+) is the one real dollar cap, and importantly **subagent spend counts toward the parent's cap, with running background subagents killed on breach** — which is exactly the semantics sprout needs and can inherit for free.

## Creative approaches worth stealing

### 1. Crystallization — the agent proves a behavior once, then it runs for free forever

This is the highest-ceiling idea in the literature and it is a natural fit for a harness that watches the same work repeat.

**Progressive Crystallization** (arXiv 2607.07052, Arun Malik, production incident-response system) defines a three-stage taxonomy — fully agent-orchestrated → hybrid → fully deterministic — with an **evidence-based promotion mechanism**: a behavior validated enough times is converted into a deterministic workflow, and **automatic demotion** returns it to agent control when it regresses. Measured over eight months in production: **deterministic execution went 0% → 45%, and per-incident agent cost fell >70% despite incident volume doubling [A]**. Quality improved, because deterministic paths are reproducible and auditable.

**LOOP Skill Engine** (arXiv 2605.14237) is the extreme version: record one successful agent run, extract a parameterized template via greedy length-descending extraction, then **replay with zero LLM calls**, resolving variables against live values. **93.3–99.98% monthly token reduction, 8.7× lower latency, output non-determinism eliminated [A]** — but only on *periodic* tasks (5-minute to 24-hour intervals), and they ship a "multi-layer degradation strategy," which is an admission that replay breaks.

The same idea appears three more times independently — one-shot agentic compilation for web automation (LLM emits a JSON blueprint once, a deterministic engine executes forever, **$0.002–0.092 per compilation**), ClawTrace (instrument a session with hooks, compile a TraceCard, distil a skill), and Anthropic's own `./skills/` directory in the code-execution post, where an agent "saves that implementation for future use." **Voyager** (arXiv 2305.16291) is the 2023 ancestor: an ever-growing library of executable skills, stored as programs, retrieved by similarity — and its skill library **transferred to AutoGPT and improved it**, which is the evidence that these artifacts are portable rather than run-specific.

**For sprout:** the harness sees every child's trajectory. When the same tool-call sequence succeeds N times across sessions, that is a script waiting to be written — and after it is written it costs zero tokens. Note the two guards both papers ship: **automatic demotion on regression**, and a fallback path when replay fails.

### 2. Compression must be *restorable*, not lossy

Manus's rule is the sharpest formulation of the pointer idea: compression strategies are **"always designed to be restorable"** — drop a web page's content but keep its URL; drop a file's contents but keep its path. The filesystem becomes "unlimited in size, persistent by nature, and directly operable by the agent itself." This converts context management from a lossy summarization problem into a **lossless indirection** problem, which is why it does not carry the 38%-constraint-violation tax that summarization does. A harness can enforce it mechanically: any eviction must leave behind an identifier sufficient to re-fetch what was evicted.

### 3. Recitation — re-inject the goal to buy attention back

Manus maintains a `todo.md` that the agent rewrites incrementally, deliberately pushing the objective **into the model's recent attention span** across a typical ~50-tool-call run. This is a cost technique disguised as a prompting trick: goal drift in a long unattended run costs an entire wasted trajectory, which dwarfs the few hundred tokens of recitation. It is also the cheap counter to the Governance Decay finding — a constraint that gets *recited* cannot get *summarized away*.

### 4. Mask tools, never remove them

Also Manus: dynamically removing a tool from the definition list invalidates the KV cache from position 0 (tools render first on all three major APIs) *and* confuses the model about actions it already took. Their answer is to keep every definition present and **mask token logits during decoding** so a state machine controls what is selectable. Anthropic has since shipped the same idea from the other direction — `tool_addition`/`tool_removal` blocks (Opus 5+, beta) that let tool sets change without a full invalidation. Either way: **the tool list is part of the cache prefix and should be treated as immutable within a session.**

### 5. Keep the failures in context

Counterintuitive and cheap: Manus deliberately **retains failed actions and stack traces** rather than cleaning them up, because it lets the model "implicitly update its internal beliefs" and stop repeating the mistake. Most compaction implementations do the opposite — errors look like noise and get pruned first. Pruning them buys tokens now and pays for repeated failures later.

### 6. Fork children that inherit the parent's cache prefix

Qwen Code's `fork` mode: the child uses the parent's **byte-identical** system prompt, tool list, and history, so its request hits the prompt cache instead of paying full price to re-establish the same context — claimed **80%+ cheaper than an independent subagent [C]**. `fork_turns` bounds how much history is inherited. Contrast the Claude Code default, where every subagent cold-starts (~3,500 tokens of system prompt + CLAUDE.md + tool schemas before any work **[C]**). For a recursive harness this is a genuine architectural fork: **children that share a prefix read at 0.1×; children that don't pay 1.0×.**

Related and easy to miss: **N children spawned simultaneously with an identical prefix all miss the cache**, because none can read what the others are still writing. Staggering the first spawn by one request turns N cache misses into 1 write + (N−1) reads.

### 7. Delta-edit the context; never rewrite it

ACE (arXiv 2510.04618) represents accumulated context as **itemized bullets** and applies small localized edits merged by **non-LLM deterministic logic** — no model call to update the context at all. The named failure it avoids, "context collapse," is exactly what repeated compaction does over a multi-hour run: each rewrite erodes detail and imposes brevity bias until the useful specifics are gone. Reported +10.6% on agent benchmarks **[A]**; the cost claim is unquantified in the abstract, so treat the *quality* argument as the reason to adopt it.

### 8. Isolation as a quality feature, not just a cost feature

Cognition's shipped code-review loop deliberately gives the reviewer a **completely clean context** — not sharing the coder's history is the point, not a compromise. Result: **~2 bugs caught per PR, 58% severe [A]**. Their reasoning is the general principle: attention is finite, so a *shorter* context detects more. This is the clearest case in the literature where the cheap option is also the better one, and it generalizes to any verification child sprout spawns.

### 9. Progressive disclosure all the way down

Anthropic's Skills and tool-search designs are the same trick applied at three levels: a skill costs only its ~100-token frontmatter until invoked; a tool costs only its name until searched for; a file costs only its path until read. The measured payoff — **85% token cut with accuracy going 79.5% → 88.1% [A]** — is worth restating because it is the cleanest cheaper-*and*-better result available. Sprout should assume the same shape for anything it injects into a child: **name it, don't paste it.**

### 10. Deterministic serialization as a cost technique

Two mundane things that silently cost real money in a harness that builds prompts programmatically: non-deterministic map/JSON key ordering (a total cache invalidator that produces no error), and timestamps or run IDs placed *before* the cache breakpoint. Manus: *"even a single-token difference can invalidate the cache from that token onward."* For a Dart harness this is a `SplayTreeMap` and a rule about where the volatile block goes — hours of work, 10× on the input bill.

### 11. Memoize by task hash, and cache the *plan* not the answer

Two safe variants of caching, both avoiding the semantic-cache trap. Exact-match tool-result memoization keyed on `(command, cwd, git HEAD, dirty-file hashes)` — a key a coding harness can actually compute, unlike a generic framework. And Agentic Plan Caching (arXiv 2506.14852), which caches **plan templates keyed on extracted intent** and adapts them with a cheap model: **50.31% cost, 27.28% latency, performance maintained [A]**. Caching a plan is far safer than caching an answer, because the plan is re-executed against live state.

### 12. Shared blackboard instead of message passing

Rather than each agent carrying a conversation, agents read and write structured artifacts to a shared file or store — agent A writes `plan.json`, agent B reads it. Blackboard-architecture work (arXiv 2507.01701) argues this makes per-agent memory modules unnecessary and "reduce[s] the overall length of prompts for all agents," enabling more discussion under a fixed token constraint. Evidence here is **qualitative only** — I found no controlled measurement — but it composes cleanly with the restorable-compression rule, and the separation it implies (**agent-local scratchpad vs team-visible state**) is a useful design boundary regardless.

## Cost observability for humans

**Almost nothing rolls cost up a tree.** Of the major platforms, only **Braintrust** ("cost is propagated from child spans to parent spans") and **LangSmith** ("aggregated values for each parent run") do hierarchical rollup by design. **Langfuse** (34k stars, MIT) computes trace `totalCost` as a **flat sum** of observations, and only `generation`/`embedding` observations carry cost — its `agent` and `tool` observation types hold none. **Arize Phoenix** rolls span→trace→session but **only token-priced LLM spans contribute** (open issue #13655). **Helicone** reconstructs its session tree from **slash-delimited path strings** (`Helicone-Session-Path: /outline/lesson-1`) rather than parent span IDs — brittle for recursion. **W&B Weave** has no rollup at all (docs show hand-summing) and its TS SDK has no cost tracking. **OpenLLMetry** emits **zero** cost attributes and still uses the legacy `gen_ai.usage.prompt_tokens` names.

**The OTel GenAI conventions moved.** They now live in their own repo, [`open-telemetry/semantic-conventions-genai`](https://github.com/open-telemetry/semantic-conventions-genai) — the old `opentelemetry.io/docs/specs/semconv/gen-ai/` pages are stubs, so anything citing them is stale. Confirmed attributes: **`gen_ai.usage.input_tokens` / `output_tokens`**, plus `cache_read.input_tokens`, `cache_write.input_tokens`, `reasoning.output_tokens`. **All are still "Development" — nothing is Stable.** `gen_ai.operation.name` (Required) includes `invoke_agent`, `create_agent`, `execute_tool`, `plan`, `invoke_workflow`; agent spans carry `gen_ai.agent.{id,name,description,version}`; metrics include `gen_ai.invoke_agent.inference_calls` and `.tool_calls`.

**Cost is absent from the spec, but the open proposal is the design worth copying.** PR #443 (`gen_ai.usage.cost.*`, opened 2026-08-09, still open) proposes `cost.amount` / `.currency` / `.source`. Two decisions in it are directly load-bearing for a recursive harness:
1. **Cost attaches only to inference spans, explicitly excluding agent/workflow spans** — so a parent is a pure sum of its subtree and nothing double-counts under recursion.
2. **The amount is frozen at emit time and must never be recomputed against a later price table** — the exact opposite of LangSmith's known behavior of not re-pricing logged traces.

Follow-up issue #484 asks for a per-class breakdown (input / output / cache / reasoning / tool), because a flat amount cannot be re-derived. **[inferred]** For sprout, freezing a per-class token quad plus a frozen dollar amount at each leaf, and summing upward, is the only scheme that survives depth-3 recursion without double-counting or drifting when prices change.

**What humans actually get shown.** The vocabulary has converged, de facto, on what `ccusage` and Claude Code display:
- **Claude Code `/usage`** — total cost, API vs wall duration, lines changed, then per-model **input / output / cache read / cache write**. Cost is computed **client-side from token counts at list price**, and resets on `/clear`. It adds a `Prompt cache (main)` line (hit %, misses, warm/cold, TTL) — **main conversation only; subagents excluded**, which is precisely the gap sprout has to fill. Plan users get an **Attribution breakdown**: share of recent usage by skill, subagent, plugin, MCP server. Anthropic's published reference points: **~$13/dev/active day, $150–250/dev/month**, and **agent teams ≈7× a standard session**.
- **Statusline** is the live surface: `cost.total_cost_usd`, `context_window.used_percentage`, `exceeds_200k_tokens`, and `rate_limits.five_hour|seven_day.used_percentage`. Critically there is a separate **`subagentStatusLine`** receiving a `tasks[]` array per child — `id, name, type, status, model, effort, contextWindowSize, tokenCount, tokenSamples` — i.e. **tokens per child are available, dollars per child are not**. Sprout can compute the dollars.
- **`ccusage`** (18.3k stars, active, v20.0.x) reads local JSONL and prices via LiteLLM's pricing file, with `--offline` cache. Its most useful primitive is the **5-hour block view**: window starts at first message, showing `🔥 Rate: 2.1k/min` and `📊 Projected: 450k`. (`blocks --live` was removed in v18 in favour of `statusline`.)
- **Claude-Code-Usage-Monitor** (8.7k stars) adds burn-rate velocity and P90 forecasting, and — uniquely and importantly — a **provenance layer that labels official `rate_limits` separately from locally-estimated JSONL cost**.

**Be blunt about the evidence:** every "how to design an agent cost dashboard" writeup I found is vendor or SEO content with no user study and no A/B data. Three primitives have actual backing and the rest is taste: **provenance labelling** (official vs estimated), **cap-with-kill semantics** (`--max-budget-usd`, where subagent spend counts against the parent's cap and running children are killed on breach), and **share-of-total attribution**.

**Framework support for tree attribution is poor across the board.** AutoGen's `gather_usage_summary(agents)` returns a **flat list, no tree**. Google ADK captures the root only and sub-agents-as-tools **do not aggregate** (adk-python#4377). CrewAI and LangGraph punt to third parties. The one framework with true parent rollup by design is the **OpenAI Agents SDK**, where a nested `Agent.as_tool()` run's usage is deliberately folded into the outer run's `context_wrapper.usage`.

**One research result worth knowing.** BOHM, *Zero-Cost Hierarchical Attribution for Compound AI Systems* (arXiv 2605.22866): build the attribution tree from routing weights already present, with **leaf attribution = the path product of root-to-leaf weights**. Kendall τ = 0.928 vs SHAP's 0.980 at **9,000× lower cost**, and τ = 0.722 recovering a 475-leaf, 4-level hierarchy **[A]**. Also: BudgetMLAgent reports **94.2% cost reduction** vs single-agent GPT-4 by cascading cheap→expensive.

## What does NOT work

**Token-level prompt compression on code (LLMLingua family).** Three independent reasons to drop it, not one. (a) Measured worst-in-class on code: LLMLingua-2 takes assertion-generation EM from 33.8 to **21.2** **[M, CodePromptZip]**; SOTA compressors manage only ~10% on code docstrings before quality breaks **[A, ShortenDoc]**. (b) The package is abandoned — PyPI's last release is 2024-04-09 despite 90k downloads/month. (c) The flagship benchmark has an **unanswered open reproduction challenge** ([issue #146](https://github.com/microsoft/LLMLingua/issues/146)) suggesting the LongBench baseline in the paper is ~6 points too low, which would erase the headline. It also costs a full small-LM forward pass over your context every turn. **Skip.**

**All soft-prompt compression (Gist, ICAE, AutoCompressor, 500xCompressor, xRAG).** Every one requires model weights. Inapplicable to a hosted-API harness, full stop — and 500xCompressor's own stated retention is **62.3–72.9%** of uncompressed capability, which is unusable for code even if it were applicable.

**Semantic caching for a coding agent.** Not a tuning problem, a structural one: a one-token diff (a line number, a path, a variable name) demands a different answer and is invisible to cosine similarity. The decisive evidence is a maintainer admission — **LiteLLM's own docs say semantic caching is a poor fit for multi-turn/agentic workloads** because sequential-turn embeddings collapse into near-duplicates and replay stale answers. GPTCache (8.2k stars) is dead (last release Aug 2024) and its "10× cost / 100× speed" README claim has **no benchmark in the repo**. Honest production hit rates are **20–45%**, and the marketed "95%" usually measures match *accuracy*, not hit *frequency*. There is also a published poisoning attack and a silent failure mode where changing the embedding model invalidates the cache semantically with no error signal.

**Query-level model routers.** The reputation rests on FrugalGPT's "up to 98%" (2023 prices, narrow classification workloads, requires labeled in-distribution data that drifts) and RouteLLM's 85% **[A]**. `lm-sys/RouteLLM` has not been pushed since **2024-08-10**. The independent number is **~35% cost at <2% accuracy loss in the best case**, with **no router topping all metrics and most over-relying on the strong model** **[M, RouterArena, ~8,400 queries]** — NotDiamond ranks #12 at $4.10/1,000 queries. RouteLLM's authors themselves write that routers trained on the same data "vary widely on the same benchmark without a clear explanation." The architectural cascade (strong planner, cheap executor) has far better evidence; the classifier does not.

**Embedding-based code RAG below ~1,000 files.** ContextBench **[M]** has a plain bash-loop agent beating embedding and graph scaffolds on file-retrieval F1 (**0.634 vs 0.390 / 0.403**), and Agentless resolves SWE-bench Lite issues at **$0.34** with no index at all. Cursor's own A/B — the honest number, not their offline benchmark — is **+0.3% overall, +2.6% at ≥1,000 files**. The pro-embedding evidence that does exist (SWE-QA 65.2% vs 46.2%) is read-only Q&A on large repos, not patch generation. **[inferred]** For sprout's typical target this is negative EV; revisit only for very large repos.

**"Just ask the agent if it can finish."** BAGEN **[M]** found **all 20 model-environment pairs systematically optimistic**, still predicting >70% feasibility after burning 60% of budget, with reliable failure prediction arriving only in the final 20% — too late to save anything. Self-reported feasibility is not a stop signal. An external supervisor watching logprobs or progress signals is (AgentStop: 15–20% saved at <5% utility loss).

**Aggressive summarization as the primary context strategy.** It is necessary as a backstop but it is not free and it is not safe: **$0.33 per condense** in one published sample, a documented case of `/compact` *increasing* usage by 56k tokens, and — the number to remember — **constraint dropped from a summary → 38% violation rate vs 0% when it survived [M]**.

**"JSON output saves tokens."** It does not; `{"sentiment":"positive"}` is ~40% *more* than the prose equivalent. The saving comes from cutting prose scaffolding, and no study isolates format as a variable. Separately, the famous "structured output destroys reasoning" result (Claude-3-Haiku GSM8K 86.5% → 23.4%) **did not survive rebuttal** — it conflated JSON-mode with constrained decoding, used unequal prompts, and used a lossy LLM answer-parser. Constrained decoding is fine.

**Anything quoting input-token savings without cache accounting.** grepai's own benchmark is the cautionary example: **−97% input tokens, −27.5% actual bill**. Cache-creation tokens dominate. Divide headline token-savings claims by roughly 3.5× to estimate the bill impact **[inferred, from that one datapoint]**.

## Takeaways for sprout

1. **Make prompt bytes byte-stable, and treat that as the top-priority feature.** Volatile fields (timestamps, run IDs, remaining-budget counters) go *after* the last cache breakpoint; JSON/map serialization gets a deterministic key order; tool definitions are immutable within a session (mask, don't remove). Expected saving: **up to 10× on input tokens**, which at Manus's 100:1 input:output ratio is most of the bill. Zero quality risk. Watch the non-monotonic minimum-cacheable-prefix per model (512/1024/2048/4096) if sprout switches models per child.
2. **Set `effort: low` and a verbosity cap on every child by default; reserve high effort for the orchestrator.** Anthropic's docs recommend exactly this for subagents. Expected: **~50–68% fewer output tokens** at −0 to −3pp on strong models (TALE, CCoT, OpenAI cookbook). Escalate effort only on a failed attempt.
3. **Use native function calling everywhere; never a hand-rolled prose tool protocol.** Measured **29.1% → 47.7%** on SWE-bench while *reducing* overthinking **[M, 3,908 trajectories]**. Free, and the largest cheaper-and-better delta in this research.
4. **Enforce the output contract in the harness, not the prompt.** A child returns a structured report of ~1–2k tokens; its transcript never enters the parent. Reject or truncate over-long returns mechanically. Cheaper *and* better — it keeps the orchestrator, the agent whose judgment matters most, out of context rot.
5. **Gate the spawn decision on published tiers.** Copy Anthropic's shape: trivial → don't spawn (1 agent, 3–10 tool calls); comparison → 2–4 children; genuinely decomposable → more. Sprout owns this decision, so it can be a rule rather than a hope. Avoiding one unnecessary spawn saves the full **15× multiplier** on that subtree. Add the practitioner heuristics as telemetry, not gospel: don't spawn below ~10k input tokens of work; flag delegation when `overhead/work > 0.3`.
6. **Consider prefix-inheriting children.** A child that reuses the parent's exact prefix reads at 0.1× instead of cold-starting (~3,500 tokens plus full-price context). Qwen Code claims **80%+** for this **[C]**. And **stagger simultaneous spawns by one request** — N parallel identical-prefix calls all miss the cache.
7. **Evict structurally before you ever summarize.** Drop stale tool results, dedupe repeat file reads, keep pointers not content. Anthropic measures **84%** token reduction from context editing alone, with *no model call* **[A]**. Only summarize as a backstop — and when you do, **re-inject every hard constraint after the summary**, because a constraint that doesn't survive the summary carries a **38% violation rate [M]**.
8. **Make every evicted thing restorable.** Manus's rule: keep the path, the URL, the query — never a lossy paraphrase. This converts context management from lossy compression to lossless indirection and avoids the summarization tax entirely.
9. **Give children grep, not an index.** Independent benchmarks favour plain bash-loop retrieval on the repo sizes sprout will mostly see; semantic tooling measurably helps only weak models. A repo map is worth prototyping at ~1–2k tokens, but note that the canonical implementation (Aider) has **published no evidence at all** that it helps.
10. **Prototype crystallization — it has the highest ceiling of anything here.** Sprout already observes every trajectory. When the same tool-call sequence succeeds repeatedly, promote it to a script that costs zero tokens thereafter. Production evidence: **0% → 45% deterministic, >70% cost reduction over 8 months [A]**. Ship the two guards the papers ship: automatic demotion on regression, and an agent fallback when replay fails.
11. **Add exact-match tool-result memoization keyed on `(command, cwd, git HEAD, dirty-file hashes)`.** Safe, boring, and computable by a coding harness in a way generic frameworks cannot. Skip semantic caching entirely.
12. **Prototype the architect/executor split before any router.** Aider measured **14× cheaper at a higher score**; PayPal measured **45.8%** on a real Claude Code workload. Do not build a query classifier — the independent evidence caps that at ~35% and it is the weaker pattern.
13. **Build cost attribution the way OTel PR #443 specifies:** attach cost only to leaf inference spans, freeze the dollar amount at emit time, and let every parent be a pure sum of its subtree. This is the only scheme that survives depth-3 recursion without double-counting or drifting when prices change. Record the per-class quad (input / output / cache-read / cache-write) at each leaf; a flat total cannot be re-derived.
14. **For the human display, copy what has converged and label provenance.** Per-model token quad plus dollars, a rolling window with burn rate and projection, share-of-total by child — and **visually separate official rate-limit data from locally-estimated cost**. Claude Code's `subagentStatusLine` already hands sprout per-child `tokenCount`, `model`, and `effort`; it does not give per-child dollars, and that gap is sprout's to fill. `--max-budget-usd` semantics (subagent spend counts against the parent's cap, children killed on breach) are the right cap model to inherit.
15. **Do not build a self-assessed stop condition.** Models are systematically over-optimistic about their own feasibility right up until the last 20% of budget. If sprout stops runs early, stop them from the *outside* on observable progress signals, and expect to pay a few points of success rate for 15–30% of wasted spend — a real trade-off, not a free win.
16. **Remember the harness itself is the variable.** Claw-SWE-Bench **[M]** found harness choice moves Pass@1 by **27.4pp** under a fixed model — nearly as much as model choice (29.4pp) — and that the same harness went **19.1% → 73.4%** on adapter quality alone. That is both the strongest argument for sprout existing and the strongest warning that these optimizations can silently destroy a good model if applied carelessly. Measure per-change, on a fixed task set.
