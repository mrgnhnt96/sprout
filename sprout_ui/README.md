# sprout_ui

sprout's web UI. Jaspr in **client** mode: the build emits a static payload with no run-time Dart,
which is what lets P3-03 embed the whole thing in the `sproutd` binary as generated byte constants
(`docs/01-plan.md` §13). Today it renders a placeholder — P3-03 serves it, P3-04 attaches it to the
`watch` WebSocket and draws the tree.

## Build and test

Both commands run **from this directory**. The `jaspr` CLI comes from the `jaspr_cli` dev
dependency, not from `dart pub global activate`, so nothing machine-global is required:

```
dart pub get
dart run jaspr_cli:jaspr build     # → build/jaspr/
dart format --output=none --set-exit-if-changed .
dart analyze --fatal-infos --fatal-warnings
dart test
```

`dart test` runs the build itself (`test/payload_test.dart`), so it takes ~30 s and needs no
separate build step first.

## The payload

Three files at the top level of `build/jaspr/`, and only those three:

| file | bytes |
|---|---|
| `index.html` | 864 |
| `main.css` | 273 |
| `main.client.dart.js` | 109,470 |

`build/jaspr/packages/` sits alongside them and is **not** part of the payload — 4.4 MB of data
files from *dev* dependencies (analyzer `fix_data`, win32 fix templates, the `test` runner's
browser host). P3-03's rsync takes the top-level files only.

## Two packages, not a workspace

`sprout_ui` and `sproutd` resolve separately and always will. `revali` (sproutd's codegen CLI)
declares `analyzer ^10.0.0`; `jaspr_builder` declares `^12.1.0`. One package declaring both does
not resolve, and a `workspace:` key is exactly how they would end up in one solve. It works only
because `revali` is a **dev** dependency of sproutd — a path dependency pulls a package's regular
dependencies, never its dev ones.

## Why this does not depend on sproutd yet

P3-04 needs to decode the protocol frames that `sproutd/lib/protocol.dart` already defines, and
copying that decoder here would be F-01 again. It cannot import them today:
`protocol.dart` reaches `dart:io` and `dart:ffi` through `store.dart`, and
`build_web_compilers` responds by **skipping the entrypoint and exiting 0** — a green build with no
JavaScript in it. See `F-07` in `docs/02-open-findings.md` for the trace and the proposed split.
`test/payload_test.dart` is what makes that failure loud instead of silent.
